# Cloud-Linked OSINTboard Boards Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Link OSINTboard boards to the currently authenticated Serverfire user and add authenticated “Save to cloud” and “Load from cloud” actions that persist boards in PocketBase instead of only browser localStorage.

**Architecture:** Keep localStorage as the existing offline/local board store. Add a small cloud-store module using the shared Serverfire PocketBase client and a dedicated `osint_boards` collection whose records are owned by `@request.auth.id`; board payloads contain the graph name, nodes, edges, and timestamps. Wrap OSINTboard in the shared `AuthProvider`, expose auth state to `App`, and add cloud actions in the existing Graph Actions drawer; unauthenticated users receive a clear login prompt rather than attempting cloud requests.

**Tech Stack:** React 19, Vite, React Flow, PocketBase, `@serverfire/shared-auth`, oxlint, Vite production build, Nginx/Cloudflare deployment.

---

## Current Context / Assumptions

- OSINTboard currently stores boards in `src/data/graphStore.js` using `localStorage` and has local Save/Load/Delete plus file import/export.
- `src/App.jsx` owns the canvas ref, graph name, modal state, and local save/load callbacks.
- `src/components/Sidebar.jsx` contains the expandable Graph Actions drawer where cloud buttons belong.
- `src/components/GraphModal.jsx` reads local graph records directly; cloud loading should use a separate cloud modal/state path or a mode that receives records explicitly, avoiding accidental mixing of local and cloud IDs.
- ServerFire already provides `@serverfire/shared-auth`, whose PocketBase singleton is at `https://auth.serverfire.net` and restores the shared `.serverfire.net` auth cookie.
- OSINTboard is a standalone Vite app and must retain `base: '/OSINTboard/'` for its deployed subpath.
- The PocketBase collection schema and API rules must be confirmed before implementation. Preferred collection name: `osint_boards`.

## Proposed PocketBase Collection

Create or provision collection `osint_boards` with:

- `owner` — relation to `users`, max select 1, required
- `name` — text, required
- `nodes` — JSON, required
- `edges` — JSON, required
- `created` / `updated` — PocketBase system timestamps

API rules:

- List/View: `@request.auth.id != '' && owner = @request.auth.id`
- Create: `@request.auth.id != '' && @request.body.owner = @request.auth.id`
- Update/Delete: `@request.auth.id != '' && owner = @request.auth.id`

The client must never trust a user-supplied owner ID for authorization; it should send the authenticated user ID only as the relation value required by the create rule, while the server rules enforce ownership.

## Risks, Tradeoffs, and Open Questions

- **Collection provisioning:** The client cannot work until `osint_boards` exists with correct PocketBase rules. This is the primary prerequisite.
- **Payload size:** Media nodes may contain base64 data. PocketBase record limits and request size should be checked; consider excluding or separately storing large media blobs if boards exceed practical limits.
- **Concurrent edits:** This plan uses last-write-wins. No collaboration/conflict resolution is included.
- **Auth expiry:** Cloud requests should catch 401/403, refresh or prompt login, and avoid silently saving locally when cloud save was requested.
- **Privacy:** Board contents may contain sensitive OSINT. Use HTTPS, strict owner rules, and avoid logging node payloads.
- **Dependency packaging:** `@serverfire/shared-auth` is currently a local ServerFire package; decide whether OSINTboard becomes part of the pnpm workspace or uses a build-time alias/file dependency.
- **Naming:** The user calls them “boards,” while existing code calls them “graphs.” Keep existing internal names where practical but label the cloud UI as boards if desired.
- **Cloud modal UX:** Confirm whether cloud Save should prompt for a name every time or quick-save to the currently loaded cloud board. Recommended: prompt for a name on first save, then quick-save updates the current cloud record.

## Final Acceptance Criteria

- Authenticated ServerFire users see only their own cloud boards.
- Cloud Save creates/updates a PocketBase board owned by the logged-in user.
- Cloud Load lists and restores boards from the server.
- Local Save/Load and file import/export continue working offline.
- Unauthenticated users receive a clear login requirement for cloud actions.
- Production build and deployed `/OSINTboard/` path work with no console errors.
- Tests, lint, build, and manual ownership isolation checks pass.
